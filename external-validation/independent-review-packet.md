# 独立技术与中文编辑审阅包

目标是让三名独立审阅者在不依赖维护者口头解释的情况下，对同一个候选 commit 给出可复验结论。审阅者先记录利益冲突声明，再按角色抽样；任何 P0/P1 必须关联 Issue、修复提交和复验结果。

## 共同输入

- `README.md`、`PROJECT_STATUS.md`、`FINAL_ACCEPTANCE.md` 和完成矩阵；
- 由同一 commit 生成的 HTML、PDF、EPUB、培训 PPTX、`RELEASE_MANIFEST` 与 SHA-256；
- Python 3.12 安装命令、254 项测试、十项目运行说明和质量审计；
- P0—P9 路线图、声明边界、版本核对清单、许可文件和参考资料。

每位审阅者至少记录 6 个实际抽样文件或产物，不接受只阅读首页后给出结论。

## Agent 工程审阅

必须覆盖第 8—10、13—15、17—22、28—31、32—38 章中的至少 8 章，并实际运行项目 2、4、8、10。检查模型与 Runtime 边界、Tool 权限与幂等、RAG 引用、Memory 写入、Checkpoint 恢复、终止条件、评估、安全和成本降级。重点寻找：把 Mock 冒充 Provider、把健康检查冒充业务成功、隐式无限循环、跨租户状态泄漏和无法恢复的副作用。

## Python 工程审阅

必须安装 Python 3.12 环境，运行根测试、Ruff、mypy，并抽查项目 4、8、10 的异步取消、数据库路径、迁移、租户过滤和恢复测试。检查类型边界、Pydantic 校验、timeout、有限重试、日志脱敏、依赖固定、Docker 非 root 与只读文件系统。若无法运行某项，必须记录环境与原因，不得以源码浏览替代运行通过。

## 中文技术编辑审阅

至少逐字审读第一节、每篇首章、框架敏感章节、三个项目章页、术语表、索引和参考资料；抽检 HTML、PDF、EPUB。检查定义一致性、句子完整、图文对应、图号、代码围栏、引用、版本日期、争议观点边界、练习与答案可定位性。不得把维护者的自动编辑审计等同于独立出版校对。

## 严重度和结论

| 级别 | 定义 | 关闭要求 |
|---|---|---|
| P0 | 无法安装/构建、严重安全或权利风险、核心结论错误 | 必须修复并由原审阅者复验 |
| P1 | 重要代码不可运行、关键章节误导、明显出版缺陷 | 必须修复并由原审阅者复验 |
| P2 | 局部可用性、解释或测试深度不足 | 有负责人、期限和处置结论 |
| P3 | 风格、扩展建议或非阻塞优化 | 可进入后续版本计划 |

只有 `decision: pass` 且开放 P0/P1 均为 0，才满足对应独立审阅门禁。条件通过不能用于关闭 P9。
