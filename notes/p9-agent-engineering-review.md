# P9 Agent 工程角色复审

复审日期：2026-08-08。复审身份是仓库维护者按“Agent 系统工程师”角色执行的内部复审，不是独立外部专家背书。

## 范围与结论

复审覆盖 38 章的 Agent Runtime、Tool Calling、MCP、RAG、Memory、工作流、多 Agent、安全、评估和架构边界，以及十项目 CLI、服务接口、持久状态、权限、审批、审计、恢复和终止条件。内部角色结论为 **通过，但不升级为外部验证**。

| 维度 | 证据 | 结论 |
|---|---|---|
| 模型与 Runtime 边界 | 正文明确模型只建议工具动作，Runtime 执行校验、权限、预算和终止 | 通过 |
| 确定性与非确定性分离 | Workflow、Agent Loop、State、Checkpoint 和 Handoff 分层说明 | 通过 |
| 工具安全 | 参数 Schema、超时、幂等、审批、最小权限和审计均有代码/测试 | 通过 |
| RAG 与 Memory | 文档质量、ACL、检索、重排、引用、评估、写入和遗忘边界完整 | 通过 |
| Multi-Agent | 共享状态、消息预算、无效对话、死锁与终止条件均有反模式说明 | 通过 |
| 生产恢复 | 项目 4、8、10 有离线恢复证据；其余项目达到服务模板 | 在声明边界内通过 |
| 外部系统 | 真实 Provider、OIDC、远程 OAuth、规模与灾备未完成 | 不得标记外部通过 |

## 本轮问题处理

容器实跑发现静态配置审计未覆盖运行时状态路径。项目 4、8 的次级数据库无法在只读根文件系统创建，已改为统一写入持久卷并复验。该问题说明 Agent 的“状态”不只包括主 Run 表；索引 Pipeline、研究 Journal、导入暂存和副作用 Outbox 都必须进入部署状态清单。

## 保留意见

独立 Agent 工程师仍需抽查敏感技术结论、真实模型行为和至少一个外部 Provider 纵向链路。完成前，38 章保持 `publishable_draft`，十项目不升级为 `externally_validated`。
