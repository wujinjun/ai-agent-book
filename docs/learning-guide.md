# 学习指南

学习时间包含阅读、编码和复盘。每周的“检查标准”必须能通过运行、演示或书面解释验证，而不是“看完了”。

## 路线 A：8 周快速入门

| 周 | 章节 | 时间 | 编码任务 | 输出成果 | 检查标准 |
|---:|---|---:|---|---|---|
| 1 | 1—2 | 8h | Token 统计器 | 成本实验报告 | 能解释上下文不等于记忆 |
| 2 | 3—5 | 10h | Attention 与语义搜索 | 两个 Notebook/脚本 | 能说明采样与检索边界 |
| 3 | 6—7 | 8h | 结构化抽取器 | 带校验的 JSON API | 非法输出有失败路径 |
| 4 | 8—9 | 10h | 工具调用 Agent | 项目 2 原型 | 工具超时与循环有上限 |
| 5 | 11—13 | 10h | 最小 MCP 与 RAG | 本地知识问答 | 回答包含可追踪来源 |
| 6 | 17、23—24 | 10h | Agent 服务化 | FastAPI + 测试 | 无密钥时测试仍可运行 |
| 7 | 28—31 | 8h | Trace 与评估 | 20 条黄金集 | 能发现一次回归 |
| 8 | 项目 1—2 | 12h | 整理、容器化 | GitHub 展示项目 | 新环境按 README 可启动 |

## 路线 B：12 周系统学习

前 8 周沿用路线 A，但第 8 周只完成项目 2；随后增加：

| 周 | 章节 | 时间 | 编码任务 | 输出成果 | 检查标准 |
|---:|---|---:|---|---|---|
| 9 | 14—16 | 10h | 混合检索与重排 | 检索评估报告 | 对比至少两种切分策略 |
| 10 | 18—22 | 12h | 同一流程的两种框架实现 | 选型 ADR | 能指出抽象和锁定成本 |
| 11 | 25—27 | 10h | 状态持久化与任务队列 | 可恢复长任务 | 进程重启后状态可恢复 |
| 12 | 项目 4 或 8 | 14h | 集成、部署与评估 | 可演示系统 | 构建、测试、引用、Trace 均可查 |

## 路线 C：24 周深入学习

前 12 周采用路线 B；第 13 周开始逐步把知识库项目扩展为具备数据治理、异步执行、观测、安全和产品边界的作品。高级主题不要求同时采用全部框架，而要求用对照实验说明为什么使用或不使用某项复杂能力。

| 周 | 章节 | 时间 | 编码任务 | 输出成果 | 检查标准 |
|---:|---|---:|---|---|---|
| 13 | 23—25 | 10h | 重整项目结构，定义状态所有权和存储 Schema | Python 工程 ADR + 数据模型 | Session、Run、Checkpoint、Memory、Audit 不混用 |
| 14 | 26—27 | 12h | 增加容器、健康检查、持久 Job、取消与重试 | 可恢复异步服务 | 进程重启后任务状态收敛，写副作用不盲目重放 |
| 15 | 28—29 | 10h | 接入 Trace，建立 30—50 条 Golden Dataset | Trace 样例 + 评估报告 | 能从失败样本定位模型、工具或检索阶段 |
| 16 | 30—31 | 12h | 完成威胁建模、成本预算和降级实验 | 威胁模型 + 成本/延迟报告 | 零越权样例，报告单位成功成本和 P95 |
| 17 | 32 | 10h | 为同一任务实现单 Agent 和 Supervisor 两种方案 | Multi-Agent 对照实验 | 多 Agent 有可量化净收益，否则保留单 Agent |
| 18 | 33 与项目5 | 12h | 实现 Repo Map、Diff 分析、最小 Patch 与验证 | Code Review Agent | 不修改范围外文件，失败 Patch 可回滚并有证据 |
| 19 | 34 | 10h | 实现受限 Browser 工作流和操作审批 | Browser Agent 原型 | 页面变化可恢复，提交类动作必须人工确认 |
| 20 | 35 | 12h | 建立 OCR/表格/图像证据统一模型 | 多模态文档实验 | 结论能回到页面区域或时间码，解析错误可定位 |
| 21 | 36 | 12h | 分别设计模块化单体和微服务架构 | 两份架构图 + 拆分 ADR | 每个服务有状态所有权和明确拆分触发条件 |
| 22 | 37 | 12h | 完善流式体验、中断、重试、审批与 SLA | 产品就绪清单 | 用户能够区分运行中、暂停、失败、未知和完成 |
| 23 | 38 与项目10 | 14h | 完成框架选型、平台能力边界和退出路径 | 技术选型 ADR + 平台原型 | 权限、租户、状态、成本、锁定和迁移边界明确 |
| 24 | 全书复盘 | 16h | 清理仓库、录制演示、撰写技术说明与复盘 | 作品集、演示视频、复盘报告 | 陌生工程师可按文档复现，并解释三个关键取舍 |

24 周路线的每周固定节奏是：约 3 小时阅读、5 小时编码、2 小时测试评估、1—2 小时整理技术决策。若检查标准未通过，应缩小当周功能范围并补齐证据，不把“读完章节”视为完成。
