# 章节题库与综合考试

## 使用说明

章节题用于课前诊断和课后检查，不建议直接作为闭卷考试原题。参考答案给出评分关键词，学员可以使用不同表述，但必须说明边界和工程后果。

## 38 章基础题

| 章 | 问题 | 参考答案要点 |
|---:|---|---|
| 1 | LLM、聊天产品和 Agent 有何区别？ | 模型提供生成能力；产品组合 UI、策略与服务；Agent 增加状态、工具、循环和治理 |
| 2 | 上下文窗口为什么不是长期记忆？ | 只对当前请求可见；会截断且成本随长度变化；长期记忆需要持久化和检索策略 |
| 3 | Query、Key、Value 的工程直觉是什么？ | Query 表示当前需要的信息，Key 表示可匹配特征，Value 承载被聚合内容 |
| 4 | Temperature 与可重复性是什么关系？ | 温度影响分布平坦程度，但服务端实现、模型版本和并行也影响复现 |
| 5 | 稠密检索何时不如关键词检索？ | 精确编号、专有名词、短字段和分布外词；可用混合检索补偿 |
| 6 | Prompt 与 Context Engineering 的边界是什么？ | 前者组织指令与示例；后者管理进入模型的完整信息、工具、状态和预算 |
| 7 | 为什么 JSON 提示不等于结构化输出？ | 缺少 Schema 级约束和校验；仍可能缺字段、错类型或输出额外文本 |
| 8 | 模型发出 Tool Call 后谁执行函数？ | Agent Runtime；它负责校验、授权、执行、超时和回传结果 |
| 9 | Workflow 与自治 Agent 如何选择？ | 稳定路径优先工作流；开放决策才引入 Agent，并限制状态和终止条件 |
| 10 | Reflection 何时会有负收益？ | 简单任务、无新证据、成本敏感或评价器不可靠时会增加延迟和自洽错误 |
| 11 | MCP 与 REST API 的关系是什么？ | MCP 标准化能力发现和模型上下文交互；底层业务仍可由 REST 实现 |
| 12 | MCP Server 为什么不能信任客户端传入的“已授权”？ | 授权必须在资源所有者侧验证，客户端声明不构成信任根 |
| 13 | RAG 链路中检索成功为何仍可能答错？ | 文档质量、切分、重排、上下文组织、生成和引用映射均可能失败 |
| 14 | Query Rewriting 的主要风险是什么？ | 改写偏离原意、丢失实体或扩大权限范围；需保留原查询并评估 |
| 15 | Memory 与 RAG 的关键区别是什么？ | Memory 关注主体经历和偏好写入；RAG 关注外部知识检索，但实现可共享存储 |
| 16 | HNSW 参数调整体现什么权衡？ | 召回、内存、构建时间和查询延迟之间的权衡 |
| 17 | 原生 API 实现 Agent 的学习价值是什么？ | 暴露消息、工具循环、状态和错误语义，便于理解框架抽象成本 |
| 18 | Handoff 与普通工具调用有什么不同？ | Handoff 转移对话/责任边界；工具调用完成受限动作后仍回到原 Agent |
| 19 | 类型安全为什么不能保证模型事实正确？ | 类型只约束结构和程序边界，不验证事实来源与语义真实性 |
| 20 | LangGraph Checkpoint 不能自动解决什么？ | 外部副作用幂等、业务补偿、权限和数据一致性仍需工程设计 |
| 21 | 何时应避免使用大型 RAG 框架？ | 链路简单、强可控性/依赖约束高或团队无法承担升级和抽象调试成本时 |
| 22 | 多 Agent 角色增多为何可能降低质量？ | 通信噪声、状态冲突、成本、延迟和终止难度增加 |
| 23 | async/await 不会自动解决什么？ | CPU 密集、无界并发、共享状态竞争和阻塞库调用 |
| 24 | SSE 与 WebSocket 如何选择？ | 单向流式优先 SSE；需要双向低延迟交互时考虑 WebSocket |
| 25 | Redis 能否成为所有 Agent 状态的唯一真相源？ | 通常不应；需根据持久性、一致性、查询和恢复要求分层存储 |
| 26 | Secret 为什么不能只靠 `.gitignore`？ | 可能已进入历史、日志或镜像；需外部 Secret 管理、扫描和轮换 |
| 27 | 重试为什么会放大事故？ | 无幂等和退避时重复副作用、形成重试风暴并耗尽下游容量 |
| 28 | Trace 与日志的区别是什么？ | Trace 关联一次请求跨组件因果链；日志记录离散事件，二者互补 |
| 29 | LLM-as-Judge 的主要校准方法是什么？ | 与人工标签对照、盲测顺序、重复测量、明确 Rubric 和偏差分析 |
| 30 | Indirect Prompt Injection 为什么危险？ | 恶意指令藏在工具读取内容中，可能借 Agent 权限触发外传或副作用 |
| 31 | 降低 Token 成本为什么可能降低总效率？ | 压缩过度导致失败和重试；应以任务成功成本而非单次调用成本优化 |
| 32 | Supervisor 模式的单点风险是什么？ | 路由偏差、上下文瓶颈、成本集中和错误决策扩散 |
| 33 | Coding Agent 为什么需要 Sandbox？ | 仓库内容和命令不可信；限制文件、网络、进程与凭证影响范围 |
| 34 | Browser Agent 测试为何比普通 API 测试脆弱？ | DOM、布局、会话和异步页面变化；需语义定位、恢复和视觉基线 |
| 35 | 多模态 RAG 多了哪些评估维度？ | OCR/视觉解析、跨模态对齐、区域引用、媒体成本和隐私 |
| 36 | 模块化单体何时优于微服务？ | 团队和规模有限、边界尚在演化、需要事务一致性和低运维成本时 |
| 37 | 从 Demo 到产品最先应收紧什么？ | 用户边界、权限、副作用、失败恢复、评估和成本，而非增加更多自治 |
| 38 | 技术选型为什么必须包含“原生 API”基线？ | 识别框架提供的真实增益、锁定和复杂度，避免只比较框架宣传功能 |

## 综合考试（100 分）

1. **架构题（25 分）**：为跨部门知识库 Agent 画出包含 ACL、版本化索引、引用、审批和 Trace 的架构，说明三种失败恢复。
2. **调试题（20 分）**：系统回答无关内容。给出从数据、检索、上下文到生成的分层诊断计划，禁止直接以“改 Prompt”作为第一步。
3. **安全题（20 分）**：外部网页要求 Agent 上传本地配置。识别攻击链，设计预防、检测、审批和审计控制。
4. **评估题（20 分）**：设计一个 50 条黄金集，说明任务成功率、工具准确率、检索指标和人工复核如何组合。
5. **选型题（15 分）**：比较原生 API、PydanticAI 与 LangGraph 实现可恢复审批流程的取舍，并写出迁移策略。

### 综合考试评分要点

架构题必须明确状态所有权与信任边界；调试题必须逐层用证据排除；安全题必须包含最小权限和副作用审批；评估题必须区分离线指标与线上结果；选型题必须讨论控制力、类型、持久化、测试与锁定。只列框架功能不超过该题 40% 得分。
