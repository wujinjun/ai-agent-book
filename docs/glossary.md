## Agent 机制

| 术语与别名 | 定义 |
|---|---|
| Action（动作） | Agent 选择执行的下一步操作，例如调用工具、请求确认、移交或结束任务。 |
| Observation（观察） | Agent 在一步执行后从工具、环境或用户获得并写回状态的可用信息。 |
| Planning（规划） | 在执行前或执行中形成目标、子任务、依赖和完成条件的过程。 |
| ReAct（Reason and Act） | 交替进行推理、动作和观察，使模型能够利用外部反馈逐步完成任务的 Agent 模式。 |
| Reflection（反思） | 根据执行结果与评价标准检查缺陷并提出修正的过程，不应被当作必然提升正确率的保证。 |
| Routing（路由） | 根据请求特征、风险和能力边界选择模型、工具、工作流或处理者的控制决策。 |
| State（状态） | 工作流在当前时刻保存的任务事实、消息、工具结果、控制字段和恢复信息。 |
| Termination Condition（终止条件） | 判定 Agent 循环完成、失败、超预算或需要人工介入的显式规则。 |
| Tool（工具） | 由宿主程序向模型暴露名称、说明和参数 Schema，并在受控边界内执行的外部能力。 |
| Tool Registry（工具注册表） | 保存工具元数据、版本、权限、执行器和审计策略，并支持发现与路由的管理组件。 |

| MCP Client（MCP 客户端） | 在模型应用一侧连接 MCP Server、协商能力并调用工具或读取资源的协议参与方。 |

| MCP Server（MCP 服务端） | 通过 MCP 暴露工具、资源或提示并执行访问控制的服务端程序。 |
| MCP Transport（MCP 传输 / Transport） | MCP Client 与 Server 交换协议消息的通道，例如本地 stdio 或规范定义的远程传输。 |

## 安全

| 术语与别名 | 定义 |
|---|---|
| Allowlist（允许列表 / 白名单） | 仅允许显式批准的工具、参数、目标或数据范围通过的默认拒绝策略。 |
| Audit Log（审计日志） | 对身份、授权、输入摘要、工具动作、审批和结果进行防篡改或可追溯记录的日志。 |
| Data Exfiltration（数据外泄） | 数据通过未授权工具调用、提示、日志、网络请求或输出离开可信边界的安全事件。 |
| Excessive Agency（过度代理权） | Agent 被授予超出任务所需的权限、自治范围或执行能力，从而放大错误和攻击影响。 |
| Guardrail（护栏） | 在输入、动作和输出边界实施校验、权限、审批与内容策略的控制机制。 |
| Indirect Prompt Injection（间接提示注入） | 恶意指令隐藏在网页、文档、邮件或工具结果中，并在被 Agent 读取后影响其决策的攻击方式。 |
| Least Privilege（最小权限） | 只向主体授予完成当前任务所需的最少资源、动作和有效期权限的原则。 |
| PII（Personally Identifiable Information / 个人可识别信息） | 能够单独或结合其他数据识别自然人的信息，需要按适用法规和组织策略保护。 |
| Prompt Injection（提示注入） | 攻击者通过输入或间接内容诱使模型偏离可信指令、泄露数据或滥用工具的攻击方式。 |
| Sandbox（沙箱） | 通过进程、文件系统、网络、凭证和资源限制隔离不可信代码或工具执行的环境。 |
| Threat Modeling（威胁建模） | 系统识别资产、信任边界、攻击者能力、滥用途径和缓解措施的安全设计过程。 |

## 工作流

| 术语与别名 | 定义 |
|---|---|
| Checkpoint（检查点） | 对工作流状态进行持久化的快照，用于恢复、中断、回放和人工介入。 |
| Dead Letter Queue（DLQ / 死信队列） | 保存超过重试限制或无法处理任务的隔离队列，供诊断、修复和受控重放。 |
| Fencing Token（栅栏令牌） | 单调递增的所有权序号，用于阻止已失效工作者继续写入共享资源。 |
| Handoff（移交） | 将任务、状态或控制权从一个 Agent 明确转交给另一个 Agent 的协作模式。 |
| Human in the Loop（HITL / 人工介入） | 在高风险或不确定步骤暂停自动执行，由人类检查、修改或批准后继续。 |
| Lease（租约） | 在有限有效期内授予工作者处理任务的权利，过期后允许其他工作者接管。 |
| Outbox Pattern（事务发件箱 / Transactional Outbox / Outbox） | 将业务变更与待发布事件写入同一事务，再由独立发布器投递，以降低双写不一致风险。 |
| Workflow（工作流） | 由显式节点、状态与转移规则约束的执行过程。 |

|---|---|

| Context Engineering（上下文工程） | 围绕任务选择、组织、压缩并验证模型可见信息的系统工程方法。 |
| Dependency Injection（依赖注入） | 由外部向组件提供依赖而非在组件内部创建依赖的设计方式，有利于测试、替换和权限隔离。 |

| Idempotency（幂等性） | 同一请求被重复执行时仍产生与执行一次等价的可观察结果，是工具重试和任务恢复的重要边界。 |
| JSON Schema | 描述 JSON 数据类型、必填字段、取值约束和嵌套结构的机器可读规范。 |

| SSE（Server-Sent Events） | 服务器通过单向长连接持续向客户端推送事件的 HTTP 机制，常用于 Agent 流式响应与进度更新。 |

| Timeout（超时） | 为模型、工具、网络或任务执行设置的最长等待时间，用于阻止资源无限占用。 |
| WebSocket | 在单一连接上支持客户端与服务器全双工消息传输的协议，适用于需要双向实时交互的 Agent 会话。 |

| Tool Calling（Function Calling / 工具调用） | 模型产生结构化工具意图，由宿主程序校验并执行，再把结果返回模型的交互模式。 |

## 检索

| 术语与别名 | 定义 |
|---|---|
| Chunking（文本切分 / 分块） | 将文档拆成适合索引与检索的片段，同时保留语义完整性、来源位置和元数据的过程。 |
| Citation（引用） | 把生成主张关联到可定位来源片段的机制，既服务读者核验，也支持评估与审计。 |
| Dense Retrieval（稠密检索） | 将查询和文档映射为稠密向量，再通过近邻搜索查找语义相关候选的方法。 |
| Embedding（嵌入向量） | 将对象映射为数值向量，以便计算相似性或供下游模型使用的表示。 |
| Grounding（依据约束） | 用可追溯的外部数据约束生成，使回答能够关联证据。 |
| HNSW（Hierarchical Navigable Small World） | 通过多层近邻图实现高召回近似向量搜索的索引结构。 |
| Hybrid Search（混合检索） | 联合稀疏检索、稠密向量检索或其他信号并融合排序的检索方法。 |
| IVF（Inverted File Index） | 先按聚类中心缩小候选分区，再在选定分区内搜索的近似向量索引方法。 |
| Metadata Filtering（元数据过滤） | 在检索前或检索中按租户、权限、时间、文档类型等结构化字段限制候选集合。 |
| pgvector | 为 PostgreSQL 提供向量类型、距离运算符和近似索引能力的扩展。 |
| RAG（Retrieval-Augmented Generation / 检索增强生成） | 生成前检索相关外部材料并注入上下文的系统模式。 |
| Reranker（重排器） | 对初次检索候选进行更精细相关性评分并重新排序的模型或规则组件。 |
| Retriever（检索器） | 根据查询从索引或数据源返回候选证据及其分数、标识和元数据的组件。 |
| Sparse Retrieval（稀疏检索） | 基于词项、倒排索引和稀疏权重进行匹配的检索方法，BM25 是常见实现。 |
| Vector Database（向量数据库） | 为高维向量相似性检索、元数据过滤和索引维护优化的数据系统。 |

## 模型基础

| 术语与别名 | 定义 |
|---|---|
| Alignment（对齐） | 通过数据、反馈训练与运行时策略，使模型行为更符合人类意图、安全约束和产品目标的过程。 |
| Attention（注意力） | 根据查询与键的相关性对值进行加权组合的序列信息聚合机制。 |
| Context（上下文） | 单次模型调用可见的消息、指令、工具结果与检索材料。 |
| Context Window（上下文窗口） | 一次模型推理能够处理的输入与输出 Token 总量边界，不是跨会话自动保留的长期记忆。 |
| Decoder-only（仅解码器架构） | 使用因果注意力按序预测后续 Token 的 Transformer 架构，是现代生成式大语言模型的常见结构。 |
| Hallucination（幻觉） | 输出在语言上合理但缺少事实依据、与上下文冲突或无法验证的内容。 |
| KV Cache（键值缓存） | 自回归生成时复用历史 Token 注意力键和值的缓存，以减少重复计算并降低逐 Token 延迟。 |
| LLM（Large Language Model / 大语言模型） | 在大规模语料上训练、能够基于上下文建模并生成语言序列的参数化模型；它本身不等同于聊天产品或 Agent。 |
| Logit（未归一化分数） | 模型在概率归一化前为候选 Token 给出的数值分数，经过 Softmax 后形成概率分布。 |
| Pretraining（预训练） | 通过大规模数据与自监督目标学习通用表示和序列规律的训练阶段。 |
| SFT（Supervised Fine-Tuning / 监督微调） | 使用输入与期望输出样本继续训练模型，使其更稳定地遵循任务格式和指令。 |
| Temperature（温度） | 调整候选 Token 概率分布尖锐程度的采样参数；它改变随机性，但不能替代事实校验。 |
| Token（词元） | Tokenizer 处理文本时使用的离散单元，不等同于汉字或单词。 |
| Tokenizer（分词器） | 在文本与 Token ID 序列之间进行编码和解码的组件，其词表与切分算法由具体模型决定。 |
| Top-k | 只保留概率最高的 k 个候选 Token 参与采样的解码策略。 |
| Top-p（Nucleus Sampling / 核采样） | 只从累计概率达到阈值 p 的最小候选集合中采样的解码策略。 |
| Transformer | 以注意力、前馈网络、残差连接和位置表示为核心的神经网络架构族。 |

## 记忆

| 术语与别名 | 定义 |
|---|---|
| Episodic Memory（情景记忆） | 保存特定事件、时间、参与者、动作与结果的经历记录。 |
| Long-term Memory（长期记忆） | 跨会话持久化并可按需检索的信息，需要明确写入、更新、遗忘和隐私策略。 |
| Semantic Memory（语义记忆） | 对稳定事实、概念和用户偏好的抽象存储，不强调事件发生的完整时间序列。 |
| Short-term Memory（短期记忆） | 为当前会话或任务保留的近期消息、步骤与临时事实，通常受上下文或状态容量限制。 |

## 评估

| 术语与别名 | 定义 |
|---|---|
| Faithfulness（忠实度） | 生成内容中的主张是否能够由给定证据支持的评估维度。 |
| Golden Dataset（黄金数据集） | 由代表性输入、期望行为、证据和评分标准组成的稳定评估集合，用于回归和版本比较。 |
| LLM-as-Judge（模型裁判） | 使用模型依据明确量表评判输出质量的方法，必须通过人工抽检、位置偏差测试和一致性分析校准。 |
| MRR（Mean Reciprocal Rank / 平均倒数排名） | 首个相关结果排名倒数的平均值，用于衡量相关结果是否靠前。 |
| Recall@K（召回率@K） | 前 K 个检索结果中覆盖相关文档或答案证据的比例。 |
