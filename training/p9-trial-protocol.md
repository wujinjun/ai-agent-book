# P9 真实试学与企业试讲协议

版本：1.0；制定日期：2026-08-08。本协议用于收集真实参与者证据，不能由仓库自动测试或维护者自评替代。

## A. 个人学习试验

至少招募 3 名有软件工程经验、但未系统学习 Agent 的参与者。参与者从全新环境开始，完成 README Quick Start、第 8—9 章、项目 2，以及第 13 章与项目 4 的最小 RAG 路径。记录安装时间、求助次数、失败点、练习正确率、项目完成率和主观负担。

通过标准：3/3 能在 15 分钟内打开 HTML 并运行离线 Tool Loop；至少 2/3 无维护者代操作完成项目 2；核心练习平均正确率不低于 80%；所有阻塞性反馈有 Issue、负责人和关闭证据。

## B. 企业培训试讲

至少组织 1 次 6—12 人、时长不少于 4 小时的试讲，讲师只使用仓库的讲师手册、幻灯片、实验手册、Fixture 和评分标准。课程至少覆盖 Tool Calling、RAG、安全与评估四个主题，并执行一个工作坊。

通过标准：环境成功率不低于 90%；核心实验完成率不低于 80%；课前/课后同题测验平均提升不少于 20 个百分点；讲师能够不修改仓库材料完成授课；P0/P1 反馈全部关闭。

## 反馈记录模板

| 字段 | 填写要求 |
|---|---|
| 参与者编号 | 匿名编号，不收集姓名、公司邮箱或电话 |
| 背景 | 年限区间、主要技术方向、Python 熟悉度 |
| 环境 | OS、CPU 架构、Python、浏览器/阅读器 |
| 任务 | 章节、实验或项目编号 |
| 结果 | 成功、部分成功、失败；附去敏日志或截图 |
| 用时与求助 | 分钟数、求助次数和具体卡点 |
| 严重度 | P0 阻塞、P1 关键错误、P2 可用性、P3 建议 |
| 负责人/期限 | 仓库维护者与目标关闭日期 |
| 复验 | 修复提交、复验参与者和结果 |

原始反馈只保留匿名编号和必要技术信息；自由文本发布前执行隐私审查。试学完成后汇总到 P9 接受矩阵，不提交含个人身份的信息。
